## ⌨️ Comandos y pasos importantes

- `git --version` — comprueba que la instalación de Git se ha realizado correctamente en el sistema.
- `ssh-keygen -t ed25519 -C "tu-correo-de-github"` — genera un nuevo par de claves criptográficas SSH (algoritmo Ed25519) específico para el ordenador de casa.
- `cat ~/.ssh/id_ed25519.pub` — muestra el contenido de la clave pública SSH para copiarla e introducirla en GitHub.
- `git config --global user.name "Tu Nombre"` — establece el nombre de usuario de Git a nivel global en la máquina.
- `git config --global user.email "tu-correo-de-github"` — establece la dirección de correo vinculada a Git a nivel global.
- `ssh -T git@github.com` — comprueba y confirma la conexión de autenticación por SSH con los servidores de GitHub.
- `mkdir -p RUTA_SOR/Boveda_SOR/00_Apuntes` — crea la estructura de directorios contenedor para los apuntes en el disco local.
- `mkdir -p RUTA_SOR/Boveda_SOR/01_Practicas` — crea la estructura de directorios contenedor para las prácticas en el disco local.
- `git clone git@github.com:TU-USUARIO/apuntes-sor-t1.git Trimestre_1` — clona el repositorio de apuntes asignándole directamente el nombre de carpeta local `Trimestre_1`.
- `git clone git@github.com:TU-USUARIO/bloque-0-prerequisitos.git B0_Prerrequisitos` — clona el repositorio del Bloque 0 dentro de la carpeta de prácticas.
- `git clone git@github.com:TU-USUARIO/bloque-1-entorno.git B1_Entorno` — clona el repositorio del Bloque 1 dentro de la carpeta de prácticas.
- `git clone git@github.com:TU-USUARIO/bloque-2-ubuntu-local.git B2_Ubuntu_Local` — clona el repositorio del Bloque 2 dentro de la carpeta de prácticas.

## 🤔 Respuestas a las preguntas

1. **¿Por qué clonas desde GitHub en vez de copiar con pendrive?** Porque en el repositorio de GitHub se encuentra la versión centralizada y actualizada de los trabajos subidos desde el aula. Clonar directamente garantiza que el estado en el equipo de casa sea exactamente idéntico al del centro sin depender de copias manuales ni introducir incoherencias entre archivos.
    
2. **¿Por qué generas una clave SSH nueva en casa?** Porque la clave privada SSH es única e intransferible por cada dispositivo físico y no se debe copiar entre ordenadores. Cada equipo requiere registrar su propia clave pública en GitHub (en este caso nombrada `Equipo Casa`), manteniendo operativa y sin alterar la clave guardada para el `Equipo Centro`.
    
3. **¿Dónde NO debe estar la bóveda?** La bóveda NO debe estar ubicada dentro de **OneDrive** ni en carpetas que cuenten con sincronización automática en la nube de Microsoft. Los mecanismos de sincronización de OneDrive interfieren con el control de versiones de Git, causando la creación de ficheros duplicados o corrupción en el repositorio. Debe permanecer siempre en una ruta estrictamente local.
