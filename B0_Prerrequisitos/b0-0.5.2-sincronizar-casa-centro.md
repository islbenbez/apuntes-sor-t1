## ⌨️ Comandos y pasos importantes

- `git pull` — descarga la versión más reciente del repositorio desde GitHub al equipo local antes de iniciar el trabajo.
- `git add .` — prepara todos los ficheros creados o modificados en la carpeta del repositorio.
- `git commit -m "Fase 0.5.2: apuntes escritos desde casa"` — registra un punto de control local con una descripción clara de los cambios.
- `git push` — sube los commits guardados localmente hacia el repositorio en GitHub.

## 🤔 Respuestas a las preguntas

1. **¿Por qué NO se mete la bóveda en OneDrive si usamos Git?** Porque son dos sistemas de sincronización independientes que entran en conflicto al gestionar los mismos archivos. OneDrive corrompe la carpeta interna `.git` y genera "copias en conflicto" (ficheros duplicados como `fichero-MiPC.md`) que invalidan el funcionamiento de `git pull`.
    
2. **Escribe el ciclo diario de tres pasos.**
    
    - **Paso 1 (Al empezar):** Ejecutar `git pull` para bajar lo último del otro equipo.
    - **Paso 2 (Trabajar):** Editar o crear las entradas requeridas en Obsidian.
    - **Paso 3 (Al terminar):** Ejecutar `git add .` → `git commit` → `git push` para subir los cambios a GitHub.
3. **¿Qué problema puede aparecer si olvidas el pull al empezar?** Puede aparecer un conflicto de versión (`CONFLICT`), debido a que se modifica localmente un archivo que ya había sido actualizado en GitHub desde el otro equipo.
